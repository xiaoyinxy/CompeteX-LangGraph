# CompeteX 产品方案与评测设计

## 核心用户与任务

核心用户：AI 产品经理、创业者、战略分析师。

核心任务：在明确时间范围、市场范围和决策目标的前提下，快速形成有证据的竞品研究初稿。

非目标：代替法律、投资或公司战略负责人作出最终决定；获取付费墙或无授权内部数据；保证网络信息绝对正确。

## MVP 范围

输入：自然语言研究目标。

处理：澄清范围、生成研究计划、并行检索、压缩证据、反思覆盖度、补充研究、生成报告。

输出：决策摘要、竞品对比、关键证据、置信度、机会与风险、待验证事项、来源列表。

## 报告质量规则

1. 重要事实必须有来源；
2. 一手来源优先于媒体，媒体优先于聚合与转载；
3. 用户社区可以支持体验判断，但不能单独证明官方能力；
4. 事实、推断和建议必须在语言上区分；
5. 无法验证时输出证据不足；
6. 时效性事实必须显示资料日期；
7. 建议必须说明依据、收益、风险和待验证假设。

## 评测集设计

准备 10 个固定任务，覆盖：

- 双竞品与三竞品对比；
- 定价和商业模式；
- 最近 90 天产品动态；
- 用户反馈与采用阻力；
- 信息稀缺的早期产品；
- 中英文来源混合；
- 存在同名产品或矛盾信息的任务。

每个任务由人工预先定义必须覆盖的维度，并抽取 5—10 条关键事实作为核验点。

## 指标定义

- 维度覆盖率：已有效回答的规定维度数 / 规定维度总数；
- 引用有效率：可访问且内容相关的引用数 / 抽查引用总数；
- 主张支持率：确实被所引来源支持的关键主张数 / 抽查主张总数；
- 一手来源占比：官方或原始资料引用数 / 全部引用数；
- 不确定性识别率：证据不足测试中正确暴露不确定性的任务数 / 此类任务数；
- 平均任务耗时：从提交到报告完成的时间；
- 单任务成本：模型与搜索调用的总成本；
- 人工可用性：评审对“是否能用于下一步决策”的 1—5 分评价。

## 失败与降级

- 搜索不可用：停止任务并明确提示，不用模型记忆冒充实时资料；
- 某竞品资料不足：保留空缺并输出待验证清单；
- 来源冲突：同时呈现并说明来源日期和权威级别；
- 达到预算上限：基于现有证据生成受限报告，标注未覆盖项；
- 模型输出结构异常：有限次数重试，之后返回可诊断错误；
- 链接失效：在评测中记为无效引用并安排重新检索。

## 版本路线

V0：跑通官方研究流程。

V1（当前）：竞品报告规范、低成本预算、本地免登录演示、中文面试文档。

V2：增加报告模板选择、来源过滤、任务成本面板和 Markdown 导出。

V3：接入公司内部知识库、定时监控竞品变化、差异提醒和团队协作审批。
